# Security TODO

This document tracks the security work that **was intentionally deferred**
during the v8 hardening pass. Each item has a category, an owner, a
"why deferred" rationale, and the next action.

## Deferred items

### 1. WebAuthn / passkeys as the primary second factor

- **Category:** authentication
- **Status:** not implemented
- **Why deferred:** SMS and TOTP codes are still in place. Switching
  to WebAuthn changes the SPA flow and the registration UX. It is a
  multi-week project, not a hot-fix.
- **Next:** Add a `WebAuthnCredential` table, register authenticators
  on login, and require ``userVerification: required`` for any
  WebAuthn-based step-up.

### 2. Argon2id KDF on the client

- **Category:** cryptography
- **Status:** documentation only
- **Why deferred:** The browser currently uses PBKDF2-SHA256 with
  600,000 iterations. The path forward is to switch the private-key
  blob derivation to Argon2id via a WASM build of libargon2 compiled
  with parameters ``memory=64MB, t=3, p=4``. The vendored noble libs
  are now local, so the WASM build is a one-time addition.
- **Next:** Bundle ``argon2-browser`` (or build libargon2 to WASM),
  update ``qv-crypto.js`` to call it instead of PBKDF2, and bump the
  ``qv-crypto.js`` schema version to ``QV-KDF-2`` so legacy blobs
  stay decryptable.

### 3. Public-key rotation proof-of-possession

- **Category:** cryptography
- **Status:** not implemented
- **Why deferred:** The v8 controller accepts a new ``public_key``
  blob from the (already-authenticated) user without requiring a
  signature over the rotation request. In a single-device threat
  model this is fine; in a multi-device model an attacker with a
  session cookie could swap the key. A proper fix needs
  ``ML-DSA-65`` signatures generated by the device that owns the
  current key.
- **Next:** Add a ``public_key_proof`` field to the registration /
  rotation endpoint, require an ``ML-DSA-65`` signature over the
  concatenation of the new public key and a server-supplied nonce,
  and verify it against the currently-registered public key.

### 4. Recovery codes (one-time backup)

- **Category:** authentication
- **Status:** not implemented
- **Why deferred:** Adds 5-10 printable recovery codes at
  registration, persisted as peppered hashes. A SPA-side generator
  is required; the UX needs design review.
- **Next:** Generate 10 alphanumeric recovery codes at registration,
  store their hashes, allow one-time consumption via a new
  ``/api/recover`` endpoint that bypasses MFA for 24 hours.

### 5. Garbage-collecting stale SRP sessions

- **Category:** operational
- **Status:** partially mitigated
- **Why deferred:** SRP state in Redis already expires via
  ``SESSION_TTL_SECONDS``. We do not have explicit cardinality
  reporting; a future enhancement is to log SRP failure rate and
  alert on bursts.

### 6. Tamper-evident audit log

- **Category:** operational
- **Status:** not implemented
- **Why deferred:** The audit logger writes one-line JSON records
  to stdout. An attacker with filesystem access can delete the log.
  A future enhancement is to forward events to an external SIEM
  (Datadog, Splunk, Loki) or to a write-once storage bucket.

### 7. HSTS preload

- **Category:** transport
- **Status:** partially implemented
- **Why deferred:** HSTS is on with a 1-year max-age and
  ``includeSubDomains``. The ``preload`` directive is not set; an
  operator must submit the domain to hstspreload.org after proving
  that every subdomain serves HTTPS.

### 8. CORS hardening

- **Category:** transport
- **Status:** functional
- **Why deferred:** The CORS allow-list is read from
  ``QV_ALLOWED_ORIGINS`` (or the hard-coded defaults). Each entry
  is a security decision that needs review. Production deployments
  should override the env var with exactly the origins they need.

### 9. Dependency SBOM and signed releases

- **Category:** supply chain
- **Status:** partially implemented
- **Why deferred:** ``requirements.txt`` is now version-pinned.
  Adding ``pip-audit`` and ``pip-compile --generate-hashes`` to CI
  is the next step; the ``make upgrade-deps`` target needs to land.

## Items completed in this hardening pass

- Application factory with secure defaults (``app_factory.py``)
- Production WSGI entry (``wsgi.py``)
- Removal of duplicate ``main.py``
- Removal of dead ``import subprocess`` in ``controllers/file.py``
- Phone verification and MFA codes stored as peppered SHA-256
  digests; ``hmac.compare_digest`` for comparison
- ``utils/security.py`` central module: audit logger, JSON CSRF
  protection, constant-time helpers
- JSON CSRF on all ``/api/srp/*`` and ``/secure_sync`` routes
- Per-username (in addition to per-IP) rate limits on SRP endpoints
- Flask-Talisman: HSTS, CSP, X-Frame-Options=DENY, X-Content-Type-Options,
  Referrer-Policy
- ``PERMANENT_SESSION_LIFETIME`` of 8 hours
- Secure / HttpOnly / SameSite=Lax session cookies
- ``UNIQUE`` constraint on ``phone`` removed
- Path-traversal guard on ``/download/<filename>``
- Bogus ``role_required('user', ...)`` removed
- Vendoring of noble crypto (sha2, hkdf, ml-kem, ed25519) into
  ``static/js/vendor/``; CDN dependency removed
- ``UserModel.is_authenticated`` and ``is_anonymous`` overrides
  removed (they were always-True/always-False and broke downstream
  consumers); ``is_active`` no longer tied to subscription status
- ``utils/scheduler.py`` rewritten to fix the ``url_for`` outside
  request context bug and replace deprecated ``datetime.utcnow()``
- ``utils/utils.py`` ``Config`` class annotated so static analysis
  can see every attribute
- ``requirements.txt`` pinned to specific versions
- ``make backupdb`` target (alias of ``cleandb``) added; the
  destructive target now requires a confirmation prompt
